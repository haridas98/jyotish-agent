# ЭТАП 3. Разделить Auth и Birth Data

## Проблема

Сейчас форма входа смешана с данными рождения:

```text

пароль
дата рождения
```

## Правильная логика

Auth — это только:

```text
логин/email
пароль
войти
зарегистрироваться
```

Данные рождения — это отдельный flow:

```text
Создать карту
Имя
Дата рождения
Время рождения
Точность времени
Место рождения
Пол
Расширенные параметры
Сохранить профиль
```

## Что сделать

### 3.1. Форма входа

Оставить только:

```text
Логин/email
Пароль
[Войти]
[Регистрация]
```

Убрать из формы входа:

```text
Дата рождения
Время
Город рождения
```

### 3.2. Создать отдельный маршрут

```text
/chart/new
```

Или использовать существующий, если уже есть.

Там сделать wizard:

```text
Шаг 1: основные данные
Шаг 2: место рождения
Шаг 3: точность времени
Шаг 4: расчётные настройки, только для астролога
Шаг 5: сохранить профиль
```

## Definition of Done

```text
- Форма входа не содержит дату рождения, время и город.
- Данные рождения вводятся только в Create Chart flow.
- После входа пользователь может создать карту.
```

# Главная мысль для агента

Сейчас проблема проекта не в том, что мало данных.

Проблема в том, что данные выводятся как простыня.

Нужно перейти от:

```text
страница = много текстовых блоков
```

к:

```text
страница = выбранный контекст + recipe + entity chips + inspector + AI evidence
```

То есть:

```text
Взаимодействия:
роль → рецепт → дома/D-карты/грахи → evidence preview → AI

Совместимость:
пара → тип совместимости → группы факторов → AI

Отчёты:
тип отчёта → что включить → preview → generate

Карта:
активная D-карта → toolbar → chart → inspector → bottom tabs
```

Если агент будет следовать этому порядку, он перестанет плодить дубли и перестанет превращать интерфейс либо в “свалку всего”, либо в пустой минимализм.
